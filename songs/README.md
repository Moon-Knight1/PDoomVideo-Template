# songs/ — 多首 MV 的工程目录

一首歌一个子目录，各自独立、互不影响。每个子目录都是一份完整可跑的工程：自带引擎、自带 `render.mjs`、自带配置。

```
songs/
├── README.md          ← 本文件
├── _template/         ← 模板，不要直接在它里面做歌
├── <歌手>-<歌名>/      ← 一首歌一个
└── ...
```

## 新建一首歌

```bash
cd songs
cp -r _template 周杰伦-晴天      # 目录名随意，建议能一眼看出是哪首
cd 周杰伦-晴天
```

然后按子目录里的 `README.md` 开工：放音频 → 改 `song.config.json` → 填 `STORYBOARD.md` → 改 `src/ch/`。

## 子目录里有什么

| 路径 | 作用 |
|---|---|
| `song.config.json` | 歌名、音频路径、时长、fps、输出名 |
| `assets/` | 这首歌的音频 |
| `src/core.js` 等 | 引擎（画法、相机、纸张、时间工具） |
| `src/lyrics.js` | 歌词时间轴 |
| `src/ch/` | 章节 = 镜头，一个文件一段 |
| `studio.html` | 加载顺序表 |
| `render.mjs` | 渲染 + 编码 |
| `STORYBOARD.md` | 分镜表（动手前先填） |
| `out/` | 渲染产物，可随时删 |

## 两点提醒

- **版权**：音频只放你确实有权使用的歌。自己听、学习、内部演示没问题，公开发布前先确认授权。
- **工程要提交**：`out/` 和 `node_modules/` 已被忽略，其余文件建议 `git add` 提交，否则工作区清理时会被删掉。
- **`node_modules` 是软链**：每个子目录里的 `node_modules -> ../../node_modules`。把某一首歌的目录整个搬走会断链，搬完在目录里重建软链，或直接 `npm i`。
